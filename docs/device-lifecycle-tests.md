# デバイスの再接続と終了の検証

番組情報取得・録画後の終了要求は、デバイスの接続が切れていても終了待ち時間後から最大2分間保持します。接続ごとに一度だけ終了指示を送り、再接続した場合に再送します。ランチャーのプロセス終了通知を受けると要求を削除し、期限切れの場合は警告を記録します。

終了指示をキューに入れただけでは送信成功とは扱いません。WebSocketへの書き込み成功を「デバイス終了指示を送信」として記録します。このログもアプリのプロセス終了を保証するものではありません。

送信直前に、後続タスクの制御権取得と直列化して以下を確認します。

- 後続予約がデバイスを取得していないこと。取得時には古い終了要求をキャンセルします。
- 他の有効な予約が実行中、または3分以内に起動予定ではないこと。DBの読み取りに失敗した場合も終了を見送ります。
- 録画状態ではなく、リモート視聴セッションも存在しないこと。
- 要求が現在も有効で、送信先が現在の接続であること。

同じデバイスの接続登録は排他的に行います。初期状態通知前でも接続は使用中とし、旧接続の受信処理が終わるまで新接続を受け入れません。

## 通知とEPGの混雑対策

Rockbar・Webアプリへの通知は録画アプリの受信処理を待たせません。通常通知のキューは4096件、字幕のキューは別途64件で、通常通知を優先します。字幕が溢れた場合は表示通知だけを破棄し、DBに保存した字幕履歴は変更しません。再生字幕も同じ優先度です。同じ送信バッチのデバイス更新・予約更新・設定更新はまとめ、検索結果や操作応答の順序は維持します。通常通知まで溢れた場合は、そのクライアントだけを切断し、再接続によって状態を取得し直します。通常のWebSocket送信は5秒で打ち切ります。

録画アプリからの現在・次番組（CPF）は即時処理します。EITは接続別のworkerで処理し、直近30分の番組はworkerを即座に起こします。それより先の番組は2秒ごとに集約し、同じ番組の通知は最新値にまとめます。受信時の放送種別を保存するため、待機中に選局が変わっても別の放送種別へ登録しません。待機上限は2048番組・概算4MiBで、混雑時は先のEPGを破棄することがあります。接続が終了した時点で未保存のEPGも破棄します。保存は最大32番組ずつのトランザクションで行います。直近番組の情報も、workerが実行中のDB処理を終えるまでは待つ場合があります。

TvRockDTV側の対応版では、EITを直近30分は100ms間隔で優先確認し、それ以外は2秒間隔・最大64番組ずつ送信します。CPFの即時送信と既存プロトコルは維持しています。サーバー側の対策だけでも旧DLLと接続できます。

対応DLLはBML関連のDSM-CC・PCR・PMT転送を既定で停止します。処理コードは保持し、録画・視聴アプリの起動引数に`/bml`を指定すると転送を有効にできます。字幕・EPG・CDTロゴは停止しません。DSM-CCは受信機向け・エンジニアリング用のロゴ候補を残します。

DSMロゴは、全ブロックを組み立てて保存できた後にだけ、サーバーから`DSMModuleReceived`で受領を通知します。保存失敗時は受領を返さず再取得し、受領通知をキューに入れられない場合も録画制御を待たせず後で再試行します。対応DLLは局・ネットワーク・TS・PID・ダウンロード・モジュール・バージョンの一致するDDBを再送しません。DIIと新バージョンは転送します。受領情報はDLLクライアントのメモリー内だけに保持します。旧DLLは追加コマンドを無視するため従来どおり受信します。

切断時の「クライアント通知の終了」「EPG受信統計」に送信件数・本文バイト数・集約件数・破棄件数を記録します。1秒以上のEPG保存処理は「EPG保存処理の遅延」として記録します。デバッグを有効にした環境の`/debug`には接続中の通知キュー統計も表示します。映像の通信量やWebSocket/TCPのヘッダーは、本文バイト数に含みません。

```powershell
go test ./tvrock -run 'Test(Controller|DeviceEPG|EITBatch|SocketWrite)' -count=1
```

大量字幕、遅いクライアントへの波及防止、状態通知の集約と応答順序、停止した受信先への送信タイムアウト、EPGの重複・放送種別・詳細情報の保持と保存失敗時の復元を検証します。これらの検証は実放送・チューナー・運用設定を使いません。

## 番組表の更新通知

Webアプリは通知による取得を直列化します。最初の通知では直ちに取得し、その後は取得開始から最低1秒の間隔を空けて、待機中の通知を種類ごとにまとめます。取得中の追加通知で応答を無効にしないため、通知が続いていても取得結果を表示できます。スクロール・日時・局の変更による取得は、この待機処理を通さず開始します。操作より前に開始した自動取得の応答は、操作後の範囲を上書きしません。

予約通知では予約一覧だけを取得し、取得済みの番組表・おすすめ番組の予約マークを差し替えます。同じ予約一覧であれば画面データを差し替えません。EPG保存時の番組表通知はサーバーから別途送ります。閉じているサイドバーの番組取得は、開くまで保留します。この変更はサーバーとWebアプリを一緒に更新してください。TvRockDTV.dllの再更新は不要です。

```powershell
node --test app/tests/uiRefreshQueue.test.cjs app/tests/frontendReview.test.cjs app/tests/deviceReconnect.test.cjs
node app/tests/uiRefreshBrowser.test.cjs
go test ./tvrock -run TestEITNotifiesGuide -count=1
```

ブラウザーテストはPlaywrightとMicrosoft Edgeが必要です。実際のVue番組表に通知1,000件と遅い取得応答を与え、追加取得の集約、スクロールの即時取得、取得範囲の保持を検証します。運用サーバー・DB・チューナーは使用しません。

## 番組検索の負荷と局の選択

局未指定時の検索は、表示有効な親サービス（`Parent == 0`または自身のSID）のみを対象とします。明示したサービスは子を含めて指定を尊重します。存在しないSIDだけを指定した場合は0件で終了し、全局検索に広げません。番組データや局設定は変更しません。

検索結果は最大200件ずつ送信し、ブラウザーは小分けに処理して、途中結果の反映間隔を最低100ms空けます。重複を除いた全結果を保持し、最終結果を時刻順に並べます。Vueの深い監視を避け、日時整形と予約状態の付加は表示する100件だけで行います。予約索引のcomputedを行ごとに参照しないことで、Vue 2による全予約の依存追跡の繰り返しも防ぎます。検索IDを指定した要求の通知には同じIDを付け、古い検索の遅延した通知を画面で破棄します。ID省略時は従来の通知形式を維持します。新しいWebアプリとサーバー本体は一緒に更新してください。

```powershell
go test ./tvrock -run 'Test(SearchServiceSelection|SearchUnknownService|SearchResponseRequestID)' -count=1
node --test app/tests/searchResults.test.cjs app/tests/frontendReview.test.cjs
node app/tests/searchResultsBrowser.test.cjs
```

EdgeとPlaywrightを使うブラウザーテストでは、検索結果1万件・予約一覧1万件の受信中の操作、表示DOMの上限100行、最終ページへの移動、予約マークの更新を確認します。運用DBや録画アプリは使用しません。

## Goの回帰テスト

```powershell
go test ./tvrock -run 'TestDevice(ConnectionRegistration|Shutdown)' -count=1
```

切断中の終了要求、再接続後の再送、送信失敗、キュー満杯、期限切れ、古い接続の後始末、後続予約・録画・視聴への引き継ぎを検証します。後続タスクが取得した後に前のタスクが終了監視を登録した場合も、待機状態になる前に監視を取り消し、「後続予約または視聴のためデバイス終了を中止」と記録します。後続利用のない終了未確認では従来どおり再試行と期限切れ警告を維持します。通常の`go test ./...`にも含まれます。

## TvRockDTVとの結合テスト

TvRockDTVのソースツリーで、検証用クライアントをビルドします。

```powershell
cargo build --locked --example device_lifecycle_probe
```

TvRockGOのルートで、生成された検証プログラムの絶対パスを環境変数に設定します。

```powershell
$env:TVROCK_DTV_LIFECYCLE_PROBE = (Resolve-Path '<TvRockDTVのソースルート>/target/debug/examples/device_lifecycle_probe.exe').Path
go test ./tvrock -run '^TestDeviceLifecycleWithRustClient$' -count=1 -v
Remove-Item Env:TVROCK_DTV_LIFECYCLE_PROBE
```

Rustの実通信クライアントとGoのデバイス受信処理を、テスト専用のループバックHTTPサーバーで接続します。切断中の終了要求が再接続後に届き、その後の再接続が止まることと、古い終了要求を残した状態でも後続の選局・録画開始・録画停止へ引き継げることを検証します。

運用設定・DB・DLL・チューナー・録画アプリは使用しません。録画コマンドはRustの模擬ホストが受信して状態を返すだけで、録画ファイルは作成しません。環境変数を省略した場合、この結合テストだけをスキップします。OSや管理サンドボックスがプロセス間のループバック通信を制限する場合は、その制限を受けない検証環境で実行してください。
