# 選局通知とチャンネル検索

TvRockGOと対応する外部アプリ・DLL間の選局仕様をまとめた技術資料です。外部アプリのソースはこのリポジトリには含まれません。導入は[README](../README.md)、サーバー側の開発・検証手順は[AGENTS.md](../AGENTS.md)を参照してください。

TSTask・RecTest・TvRockOnTVTestは、BS/CSの選局に固定のTSID・周波数対応表を使用しません。対象のチューニング空間のチャンネル一覧から、要求された親局のサービスIDを検索します。サブチャンネルが指定されている場合は、検索したチャンネルと子局のサービスIDを選局APIへ渡します。

## サービスの読み込み

`.ch2`の`;#SPACE(番号,名前)`は、番号をBonDriverのチューニング空間のインデックスとして解析し、放送種別は名前の部分一致で判定します。TVTestと同じ順序で、`地`・`VHF`・`UHF`・`CATV`を含めば地上波、次に`BS`、次に`CS`を判定します。英字の大小は区別しません。`UHF`や、番号が0以外のBS・1以外のCSも読み込めます。未知の空間名に属する局は登録せず、次の既知の空間まで読み飛ばします。

対応する`.ch2`ファイルがない場合も、デバイスへ`Ready`を返して起動を完了し、DEVICE画面の終了操作を受け付けます。ファイル欠落は`error`、不定選局状態での起動は`warn`としてデバイスIDとともにログへ記録します。既存の局情報は保持し、SDTによる局情報の登録・更新と画面への通知を継続します。`.ch2`の有無による選局・録画・番組情報取得の一律制限は行いません。

`.ch2`を読み込めない場合、初期の放送種別は設定済みのチューナー種別（地上波またはBS）を使い、以後は`STC`通知で更新します。SDTで新規登録する局の`Ch`は従来どおり0となり、既存局は保存済みの値を保持します。SDTによる局情報の取得だけで、選局に必要な情報がすべて補完されるわけではありません。

起動時の`Ready`には既存DBの表示対象サービスID一覧を付けます。`.ch2`の有無にかかわらず、SDTによって一覧が変わると、録画中などのデバイス状態を保持したまま`Ready`で更新後の一覧を送ります。これはDLLのEPG・ロゴ送信対象に反映されます。初回の`.ch2`に含まれないサブチャンネルも、SDTで登録された時点で取得対象に加わります。対応DLLは再通知を受けて保持中の番組情報を再送対象に戻すため、再起動・再選局は不要です。同じSDTの再送で一覧が変わらない場合は返信しません。

地上波フルセグTVの親は、同じ非ゼロTSIDに登録されたフルセグTVサービスのうち最小SIDのサービスです。SDTの掲載順やSIDの下位3ビットは使いません。明示的に子として指定されたサービスは自動判定の親候補から除きます。全種別に共通の`servicegroups`（tsp・parent・children）があれば、その明示指定を自動判定より優先します。未指定のBS・CS・4Kは独立扱い、ワンセグはSDTで判定した従来のフルセグとの対応を維持します。明示指定では同じ放送種別・同じ非ゼロTSIDに親候補が登録されている場合だけ子を関連付けます。親が未登録なら別のサービスを親に昇格させず、暫定的に`Parent=0`で扱い、親の登録後に再判定します。

起動時のDB読み込み後、`.ch2`の全行読み込み後、SDTのサービス登録後に、局キャッシュ全体へ同じ判定を適用します。SDTの受信一覧が一部だけでも、キャッシュ内の同じTSIDのサービス全体から最小SIDを選びます。起動時・`.ch2`読み込み時にも同じ判定を行います。以前の最小SID方式による関係も再判定するため、設定にないBSの親子関係は解除されます。Ch・サービス名・EITの有無・進行状態は親子判定に使いません。CS・ワンセグ等も共通の明示指定を使用し、Web操作・予約の選局では子SID・親SIDの順に通知します。設定例と移行方法は[設定ガイド](configuration.md#サービスの親子関係)を参照してください。

## デバイスからの通知

TvRockDTV.dllの`OnStreamChange(Channel, ServiceID)`を経由する`STC:Channel,ServiceID`通知は、BS/CSでは次の形式です。

| 値 | 内容 |
| --- | --- |
| `Channel`の上位16bit | 放送種別。BSは2、CSは3 |
| `Channel`の下位16bit | TSID。取得できない場合は0 |
| `ServiceID` | 選択中の放送サービスID（下位16bit） |

例えばBS・TSID=16625・SID=102は、`STC:147697,102`となります。TvRockGOは上位16bitから放送種別を取得するため、新しいTSIDやスキャン情報のない局でも、周波数対応表を必要としません。地上波は従来どおり物理チャンネル番号を通知します。

TSTaskとRecTestは、受信ストリームから取得したTSIDを優先し、未取得ならチャンネル一覧のTSIDを使用します。TvRockOnTVTestはホストAPIの現在チャンネル情報を使用し、TSID未取得でもBS/CSの放送種別を通知します。

この値は旧TvRockの周波数形式ではありません。TvRockDTV.dllのABIと通知の項目数は変更せず、`Channel`の内容だけを変更しています。現在のRust版DLLはこの値をそのままTvRockGOへ転送します。更新時は、この形式に対応したTvRockGOを先に配置してから各アプリを更新してください。

## サービスの親子関係

`servicegroups`で放送種別にかかわらず親子関係を指定できます。例えばBSは次のように定義します。未指定の地上波フルセグTVは、同じTSIDに登録されたフルセグTVサービスのうち、最小SIDを親として自動判定します。SDTの掲載順やSIDの下位3ビットは使いません。明示的に子として指定されたサービスは自動判定の親候補から除きます。地上波の明示指定は、この自動判定より優先します。

```yaml
servicegroups:
  - tsp: 2
    parent: 101
    children: [102, 103]
  - tsp: 2
    parent: 141
    children: [142, 143]
  - tsp: 2
    parent: 151
    children: [152, 153]
  - tsp: 2
    parent: 161
    children: [162, 163]
  - tsp: 2
    parent: 171
    children: [172, 173]
  - tsp: 2
    parent: 181
    children: [182, 183]
```

`tsp`には放送種別（1=地上波、2=BS、3=CS、4=ワンセグ、16=4K）を指定します。同じSIDでも放送種別が異なれば別サービスです。`parent`・`children`には放送波の16ビットSID（1〜65535）を十進数で指定します。TvRockGO内部の放送種別を含むSIDではありません。上の例はBS 102・103をBS 101の子にするなどの指定です。受信環境で確認した組み合わせに合わせて変更してください。SIDの先頭・末尾や名前の一致だけでは自動的に親子にしません。全種別とも、同じ放送種別・同じ非ゼロTSIDに親が登録されている場合だけ関連付けます。明示した親自身は親なしとなり、地上波の自動判定でも別の親の子にはなりません。

未定義のBS・CS・4Kサービスは独立扱いです。`servicegroups: []`または項目省略で明示指定を無効にします。地上波の自動判定と、SDTで判定したワンセグからフルセグへの既存の対応付けは維持します。ひな形には上記6組を記載していますが、既存の運用設定には自動追加されません。既存環境はサーバーを終了し、`conf/tvrock.yml`へ必要な定義を追加して再起動してください。ひな形だけの編集では既存環境に反映されません。

再起動時に既存局の親子関係も再判定します。従来の最小SID方式で付いたBSの関係は、定義がなければ解除されます。親が未登録の場合は暫定的に独立扱いとし、親の登録後に関連付けます。設定から組み合わせを削除した場合も再起動時に再判定し、地上波は登録済みサービスの最小SIDによる自動判定へ戻ります。サービスや番組データ自体は削除しません。同じ放送種別内での重複した親・子、親自身を子にする指定、親を別の親の子にする指定、範囲外のSID、未対応のtsp、空の子一覧は設定エラーになります。


この親子設定は局のグループ化・選局に使います。番組の内容の補完は、TvRockDTVから通知されるEITの共有指定（group_type=1）を使います。子自身のイベントを保存し、取得時に明示された共有先のタイトル・説明・ジャンルを参照します。録画・視聴予約とEPG追従には子のSID・EID・開始／終了時刻を使い、親のイベントIDや時刻へ置き換えません。通常・週間番組表、検索・キーワード予約でも共有先の内容を参照します。

親子設定だけを根拠に、子に存在しない番組枠を作成する処理はありません。103のようにイベント自体がないサービスは空欄のままです。サービス名が「－」であることや`running_status=0`だけによる非表示の特別処理はありません。局の表示・非表示自体は従来のサービス設定で管理します。

共有イベントに対応したTvRockDTVが必要です。旧DLLで取得済みのデータから共有先を推定して埋めることはせず、DLL更新後に番組情報を再取得してください。詳しい通知形式・DB列定義は[共有番組情報](common-events.md)を参照してください。

## 検証

- 各アプリの模擬ホストで、固定表にないTSIDのBS/CS選局・通知、TSID未取得時、サブチャンネル選局、地上波の通知を検証します。
- Goの`channel_notification_test.go`は、周波数表と局キャッシュを空にした状態でもBS/CSのSIDを復元できることを検証します。
- 運用中の録画アプリや実設定を使う自動テストは行いません。
