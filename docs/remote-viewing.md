# リモート視聴（Windows版Rockbar）

配信元PCにTvRockGOとTSTask／RecTest、またはTvRockOnTVTestを有効にしたTVTestを配置し、視聴PCのWindows版RockbarとTVTestでLAN内のストリームを受信します。ローカルのTVTestを起動・終了する機能はWindows版（Electron版）Rockbarのみ対応します。

TvRockGOが録画・視聴セッションを管理し、配信元プロセス内のTvRockDTV.dllがSRTまたはUDPで送信します。TSTask／RecTest本体の標準UDP設定とは独立しています。

導入全体は[README](../README.md)、サーバー設定は[設定ガイド](configuration.md)を参照してください。

## 準備

1. 録画PCにリモート視聴対応版のTvRockGO、TSTaskまたはRecTest、TvRockDTV.dllを配置します。録画PCのデバイス設定では、視聴用の `apppath1`／`option1` にもTSTask／RecTestのパスと起動オプションを設定します。視聴PCで起動するTVTestは、手順3のRockbar側で設定します。
TVTestを配信元にする場合は、配信元のTVTestにも対応版TvRockOnTVTestプラグインとTvRockDTV.dllを配置して有効にし、`apppath1`／`option1` にチューナーを使用するTVTestを設定します。配信元には `/parent` を指定しません。TSの復号は配信元アプリの設定に従います。

2. 視聴PCにTVTest、BonDriver_SRT.dllまたはBonDriver_UDP.dll、リモート視聴対応版のTvRockOnTVTestプラグインとTvRockDTV.dllを配置し、プラグインを有効にします。アプリとDLLのx86／x64を合わせてください。
3. Windows版Rockbarから録画PCのTvRockGOへログインします。歯車→「視聴アプリ」で、デバイスごとにTVTestの絶対パス、起動オプション、SRT・UDP受信ポートを設定し、有効にします。設定は接続先URLごとに視聴PCへ保存されます。
4. 起動オプションは、例えば `/d BonDriver_UDP.dll /nd` と指定します。`/host /pid /parent /DID /port` はRockbarが追加するため、手動指定は不要です。単一起動指定 `/s` は使用しません。受信ポートはBonDriver_UDP.dllが対応する範囲から選んでください。
5. 録画PCのTvRockGOをLANから接続できる待受アドレスにし（例: `host: "0.0.0.0:80"`）、そのTCPポートへの接続と、視聴PCのUDP受信ポートへの通信を許可します。

IPv4で直接接続するLAN構成を対象とします。送信先アドレスにはRockbarの接続元IPを使用します。リバースプロキシやNATを介した接続には対応しません。同じ視聴PCで複数のデバイスを使用する場合は、受信ポートを分けてください。

## BonDriver_SRTで受信する

配信元のTvRockDTV.dll、TvRockGO、Windows版Rockbarと、視聴PCのTvRockOnTVTestプラグインをSRT対応版へ更新します。SRTと暗号化ライブラリはTvRockDTV.dllに静的リンクされ、SRT用の追加DLLや外部送信プログラムは不要です。従来のUDP設定は引き続き使用できます。

**配信元のTSTask.exe／RecTest.exeもDLL配信モード対応版が必要です。** TvRockOnTVTest添付のパッチが適応されたアプリでしか使用できません。「SRT配信にはDLL配信モード対応の録画アプリ本体とTvRockDTVが必要」と表示されてTVTestが閉じる場合は配信元本体も確認してください。

1. 視聴PCのTVTestと同じビット数のBonDriver_SRT.dllを配置します。
2. BonDriver_SRT.iniをDLLの隣に作ります。LANで受信する場合は `ListenAddress=0.0.0.0` または視聴PCのIPv4アドレスを指定します。INIがない場合の待受は127.0.0.1なので、別PCからは受信できません。
3. Rockbarの「視聴アプリ」で配信方式をSRT、起動オプションを `/d BonDriver_SRT.dll /nd`、受信ポートを3230にします。新規設定ではSRTとこの起動オプションが初期値になり、受信ポートはデバイス順に3230から割り当てます。保存済みのUDP設定は維持します。受信チャンネルはRockbarが `/chspace 0 /chi N` で選ぶため、`/port`、`/ch`、`/chi`、`/chspace`は手動指定しません。
4. 「BonDriverの基準ポート」をINIのBasePort（既定3230）と合わせます。受信ポートは基準ポート〜基準ポート+9で指定します。送信側の最低遅延は既定120ミリ秒で、受信側の設定とネゴシエートされます。
5. 暗号化する場合は、INIとRockbarに同じ10〜79文字の印字可能ASCIIパスフレーズを設定します。空欄では暗号化しません。暗号化時はAES-256を使用します。
6. 視聴PCで選んだ待受ポートへのUDP通信を許可します。TvRockDTVがcaller、BonDriver_SRTがlistenerとして接続します。

```ini
[SRT]
ListenAddress=0.0.0.0
BasePort=3230
LatencyMs=120
Passphrase=
```

パスフレーズはRockbarのローカル設定に保存され、視聴開始時にTvRockGO経由で配信元へ渡します。状態通知やTVTestのコマンドラインには含めません。制御通信の暗号化にはHTTPS/WSSを使用してください。SRTの暗号化はTS配信に対するものです。

複数のデバイスを同じPCでSRT視聴する場合は、デバイスごとに受信ポートを分けます。基準ポート3230なら、3230は `SRT 0`、3231は `SRT 1` です。同じBonDriver_SRT.dllを複数のTVTestから使用でき、DLLの複製は不要です。同じ待受アドレス・ポートの重複は拒否します。全IPv4待受 `0.0.0.0` と特定アドレスで同じポートを使う場合も競合します。

複数同時受信には、待受アドレス・ポートごとの排他制御に対応したBonDriver_SRTと、同時視聴制限を解除したRockbarを使用してください。配信元のTvRockDTVも、複数セッションでSRTランタイムを共有する対応版へ更新します。これにより1つの視聴先を終了しても、他のSRT配信を継続できます。別PCからはそれぞれの視聴リースで同時視聴できます。

字幕・データ放送・ワンセグの選択、視聴リース、受信確認、終了処理はUDPと共通です。SRTは最大1,316バイト（188バイトTS×7）のメッセージで送り、SRT自身が再送と送信速度を管理します。UDP用のドロップ検出による平準化切り替えは適用しません。SRT非対応の配信元に接続した場合は更新を案内して終了します。

## 送信内容

歯車→「視聴アプリ」の「送信内容」で、接続先URL・デバイスごとに設定します。視聴を終了してから変更してください。

| 項目 | 動作 | 既定値 |
| --- | --- | --- |
| 現在のサービスのみ送信 | ONは選択中のサービス、OFFは同一放送波の全サービスを対象に送信 | ON |
| 字幕データを送信 | 字幕を送信 | ON |
| データ放送を送信 | データ放送を送信 | ON |
| ワンセグのみ送信 | 同一放送波のワンセグサービスを送信。「現在のサービスのみ送信」より優先 | OFF |

ワンセグが確認できない放送では開始できません。録画側の選局・録画対象は変更せず、受信側TVTestを実際の送信サービスへ合わせます。送信内容の指定には、対応版のTvRockGO、Rockbar、TvRockDTV.dll、TSTask／RecTestを使用してください。

## TVTestの局名表示

TvRockOnTVTestは、TVTest下部のステータスバーに「TvRock サービス名」を追加します。TVTestのステータスバー設定でこの項目を有効にし、表示位置を調整してください。選択中のサービスを「サービス名：　番組名」、未受信時を「サービス待ち」と表示します。既存のSRT/UDPチャンネル表示が不要な場合は、同じ設定で非表示にできます。

この項目はステータス項目の追加に対応したTVTestで利用できます。TVTest本体の変更は不要です。

## 操作

視聴アプリを有効にしたデバイスの電源ボタンで、視聴を開始・終了します。録画アプリの接続・選局と、TVTestの受信準備が完了すると送信を開始します。

- 録画中でも視聴を開始・終了できます。録画中の選局はできません。
- 予約によって録画PCの選局が変わると、視聴PCのTVTestも追従します。
- TVTestを直接閉じた場合も視聴を終了します。
- 同じ録画デバイスから複数の視聴PCへ送信できます。送信内容・送信状態・終了処理は視聴PCごとに独立します。録画デバイスごとの上限は`conf/tvrock.yml`の`remotewatch.maxsessions`で指定でき、既定は32セッションです。未指定または0以下の場合も32になります。
- 番組表やRockbarからデバイスにキャプチャーを要求すると、そのデバイスをリモート視聴中の各PCのTVTestでキャプチャーします。別のデバイスを視聴しているPCには送りません。受信準備が完了した視聴PCがない場合は、従来どおり録画側アプリに要求します。保存先は各TVTestの設定に従います。

視聴終了時は配信と視聴PCのTVTestを終了します。録画中、スケジュール実行中、または指定時間以内に起動する有効な予約がある場合は、録画アプリを残します。それ以外は録画アプリも終了します。予約状態を確認できない場合は、録画アプリを残します。

通信が切断された場合は猶予時間後に視聴を解除します。送信側も親からの状態照会が途絶えると配信を停止し、録画を継続します。再接続時には実際の送信状態を確認します。

## 予約による視聴開始

「視聴のみ」の予約と、「視聴のみ」「録画のみ」のどちらにもチェックしない予約では、録画アプリの起動・選局後、接続中のWindows版Rockbarでそのデバイスの視聴アプリ設定が有効なPCすべてのTVTestを起動します。「録画のみ」と番組情報取得の予約では起動しません。Rockbarはあらかじめ起動してログインしておいてください。実行中の予約に途中から接続した場合も対象です。

既に視聴している場合は同じTVTestを使用します。TVTestや電源ボタンから手動で終了した視聴は、同じ予約では再起動しません。予約で起動した視聴は、予約の「終了後アプリシャットダウン」が有効なら予約終了時に終了し、無効なら継続します。予約より前から手動で開始していた視聴は予約終了時も継続します。

複数PCへの送信には対応版のTvRockGO、Rockbar、TvRockDTV.dll、TSTask／RecTestを使用してください。アプリパスやオプションは各視聴PC内の設定だけを使い、サーバーから変更しません。視聴PCが未接続・起動に失敗した場合も予約録画は続けます。

## 設定

`conf/tvrock.yml` の `remotewatch` で同時視聴数の上限と待機時間を設定できます。待機時間の単位は秒です。手動編集の前にサーバーを終了し、変更後に再起動してください。

```yaml
remotewatch:
  maxsessions: 32
  keepbeforescheduleseconds: 60
  disconnectgraceseconds: 15
  startuptimeoutseconds: 60
```

| キー | 内容 |
| --- | --- |
| `maxsessions` | 録画デバイスごとの同時視聴セッション数の上限。既定32、未指定または0以下の場合も32 |
| `keepbeforescheduleseconds` | 視聴終了時に録画アプリを残す、次のスケジュール起動までの時間。スケジュール起動時刻は予約開始時刻から準備待機時間を引いた時刻です |
| `disconnectgraceseconds` | 通信切断時に視聴セッションを保持する猶予時間。5〜86400秒の範囲で使用します |
| `startuptimeoutseconds` | 視聴開始時に準備完了を待つ時間 |

未指定または正でない値には上記の既定値を使用します。変更するキーだけ運用設定に追加してください。

## アプリの起動と送信状態

視聴アプリのパスと起動オプションは、視聴PCのローカル設定画面で管理します。ネットワークから受け取った文字列で起動設定を書き換えず、シェルを介さずにアプリを起動します。終了対象はRockbarが起動したTVTestです。

録画状態、配信状態、TVTestの受信状態は個別に管理します。対応するTSTask／RecTestはUDP用の `StreamStart(address, port)`、`StreamStop()`、`GetStreamStatus(status)` を提供し、送信先・サービスID・送信量・エラーなどを通知します。SRTはTvRockDTV内の配信モードと専用の開始要求を使用します。受信の確認にはTVTest側の状態を使用します。

SRT/UDP配信はTvRockDTV.dllのRustワーカーが担当し、送信データの集約と送信バッファを共通管理します。TSTask／RecTest、またはTvRockOnTVTestを有効にしたTVTestを配信元にできます。送信性能の更新対象は配信元PCのTvRockDTV.dllです。配信モード対応への移行時は、TSTask.exe／RecTest.exe、またはTvRockOnTVTestプラグインも対応版へ更新してください。受信用TVTest（/parent指定）からは再送信しません。


## UDPのドロップ時の自動調整

通常は従来のUDP送信を使用します。受信と選局が安定してから10秒間はドロップを判定せず、その後の約1秒ごとの報告で3回連続してドロップが増加した場合、その視聴先だけ1,316バイト以下のUDPと送信の平準化へ切り替えます。起動・選局・再接続、カウンターのリセット、配信元のエラー増加があった場合は観察期間を取り直します。

平準化の送信速度は固定せず、実際の入力流量と送信待ち量に合わせます。切り替え後は視聴終了まで維持し、次回の視聴開始時に通常方式へ戻ります。録画と他の視聴先は継続します。回線や受信PCの処理能力を超える流量への対応や、失われたデータの復元を保証する機能ではありません。
